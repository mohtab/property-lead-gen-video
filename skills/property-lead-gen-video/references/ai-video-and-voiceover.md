# AI video prompts and optional voiceover

## Purpose and platform boundary

Produce usable prompt text for AI-assisted production, including tools such as Higgsfield. Do not assume a tool can generate a complete 25-second film, precise typography, a continuous edit, exact clip lengths, or synchronized voiceover from one prompt. Provide a master brief, per-shot generation prompts and a deterministic assembly plan. Keep planned edit duration separate from generated source-clip duration.

When the user names a tool, use portable plain-language prompts by default. Verify current official documentation before giving tool-specific controls, model names, syntax, settings or capability claims. If unavailable, label the pack platform-neutral; do not invent UI steps. No account or paid tool is required to write a prompt pack.

## Master creative brief

Write a self-contained block for each variation containing:
- Objective, audience, property identity and the creative premise.
- The complete eight-beat 25-second timeline and exact approved on-screen copy.
- Format, color and lighting direction, tone and continuity rules.
- Ordered visual-reference mapping using actual filenames or clearly marked reference slots.
- Required factual preservation, development-stage disclosures, CTA and destination.
- Audio direction and VO choice.
- Instructions to create source shots separately when full-film generation is unsupported, then assemble using the supplied edit timeline.

Identify this as a creative brief, not a guarantee of one-click generation. Keep unapproved facts outside release-ready copy. If a reference or fact is missing, mark the corresponding prompt provisional and say exactly what must be attached or replaced.

## Self-contained per-shot prompts

Provide a separate, copyable plain-text block for every shot requiring generation or animation. For a usable existing clip, supply a trim/edit instruction instead of unnecessary regeneration. For a logo closing card, specify editor assembly using supplied assets rather than AI-generated lettering.

Each generation block must contain:

1. Shot ID and its planned edit position and duration.
2. The reference image(s) the user should attach, identified by filename. Do not imply that a filename in a prompt automatically uploads an asset.
3. The subject, composition and action.
4. Camera framing and movement, at a restrained speed appropriate to the edit window.
5. Lighting, time of day, palette and continuity with adjacent shots.
6. What must remain unchanged in the supplied property reference.
7. Clear exclusions: no invented rooms, amenities, location features or brand marks; no warped geometry; no unintended people or props.
8. Text-safe composition and instruction to add approved typography and logos during editing.

Use complete prompt prose, not just field labels. Repeat essential reference-preservation constraints in each block so it works independently. Describe motion possible from the actual view; do not request a camera orbit that reveals undocumented architecture from a single front-facing render.

If the tool requires a source clip longer than the intended shot, request a source length supported by that tool once verified, and trim to the storyboard duration. Without verified capabilities, leave source length as tool-dependent and specify the required usable motion window. Do not change the 25-second assembly to match a generator's default length.

Use generated lifestyle content only when it can be clearly separated from factual property representation. Keep people consistent when they recur. Do not present aspirational scenes as actual residents or completed facilities.

## Assembly instructions

Provide the ordered shot list, exact trim lengths and transitions; include transitions within the total runtime. Add message overlays independently of shot cuts using the timed script. Add approved logos, price, CTA and disclosures in the editor for accuracy. Supply the actual copy so the user can paste it. Leave room around text for platform overlays and verify the final placement when a preview is available.

State which tasks remain manual or tool-dependent: attaching references, generating clips, selecting usable takes, assembling, typography, audio and export. Do not imply any of these were executed when only prompts were produced.

## Voiceover

Default to text-led films. Include VO when requested; propose it when explaining the product would materially improve comprehension. Do not narrate every title mechanically. Let narration connect benefits while on-screen text supplies the essential facts.

When providing VO:
- Write the exact spoken lines per beat with in/out times and pauses.
- Provide the complete clean recording/TTS script separately, with no timestamps or stage directions inside it.
- Specify language, accent only if requested or appropriate to the supplied brief, tone, pace and pronunciation notes for property names.
- Start around 40–50 English words for a 25-second film, then calculate speaking time against each actual window. Shorten further for pauses, prices and unfamiliar names. Treat this as an editorial estimate, not a verified read.
- Spell prices, numbers and acronyms as they should be spoken in the clean copy. Read currency and units correctly.
- For other languages, estimate and review that language's delivery independently; do not reuse an English word-count rule as proof of fit.
- Distinguish estimated timing from a measured recording. Never claim a read-through or TTS check occurred unless it did.
- Resolve any conflict between VO, on-screen copy and the fact ledger before handoff.

Close each package with a short readiness statement: what is ready to paste or hand off, and which facts or assets still require confirmation.
